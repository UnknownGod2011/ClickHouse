# TakeKeeper synthetic benchmark media

TakeKeeper's checked-in multimodal benchmark deliberately stores truth and deterministic provider responses as text. Real-model evaluation needs actual video, but large generated binaries should not live in Git.

`takekeeper.fixture_media` renders tiny, self-owned, text-free MP4 clips from the immutable truth intervals in `tests/fixtures/multimodal_eval/manifest.json`. The renderer currently supports the benchmark properties `hero_mug.hand` (`left`, `right`, `unknown`) and `maya.jacket_state` (`zipped`, `open`, `unknown`). Unknown states are represented by explicit visual occlusion rather than by a textual hint.

## Requirements

- Python 3.11+
- a local `ffmpeg` build with the `libx264` encoder

No cloud account, model key, ClickHouse instance, or Python media package is required.

## Generate the clips

Without installing the package:

```bash
PYTHONPATH=src python -m takekeeper.fixture_media \
  tests/fixtures/multimodal_eval/manifest.json
```

Or after `pip install -e .`:

```bash
takekeeper-generate-fixture-media \
  tests/fixtures/multimodal_eval/manifest.json
```

The default output directory is:

```text
.takekeeper/generated-eval-media/
```

That directory is ignored by Git. Override it with `--output-dir` if the generated assets need to be copied to private object storage for a live Gemini evaluation.

## Provenance contract

Generation writes `media-manifest.json` beside the MP4 files. The report uses schema `takekeeper-generated-media-v1` and records:

- SHA-256 of the exact benchmark manifest bytes;
- the first bounded line of `ffmpeg -version`;
- frame size and frame rate;
- case and take identity;
- relative output filename;
- MIME type and expected duration;
- artifact byte size;
- SHA-256 of the generated MP4 bytes.

The digest is evidence for the exact generated bytes, not a promise that two different ffmpeg/x264 versions will emit byte-identical MP4 containers. Archive the generated `media-manifest.json` with any live model benchmark report so the candidate can be traced to the actual input clips.

## Evaluation integrity

The renderer intentionally does not draw labels such as `left`, `right`, `open`, or `zipped` into frames. The visual geometry is generated from pre-existing truth labels. Do not modify the benchmark truth after inspecting a Gemini candidate's output. If the visual design needs to change, treat that as a new fixture-media generation version and archive its content digests.

The generator has no upload primitive. Moving generated media to Google Cloud Storage or another trusted private store is an explicit operator action so local benchmark preparation cannot accidentally publish private production media.
